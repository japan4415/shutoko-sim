# 性能計測レポート 2026-09-12 Galaxy Fold8 Ultra

issue #13 の性能目標（[delivery.md](../../delivery.md) の「性能目標と測定」）に対する**実機計測**の記録。
代理計測（`../2026-09-11-proxy-pixel5-emulation/`）は Chromium + CDP のエミュレーションであり、
特に探索時間は CPU スロットルが Web Worker に効かないため実機の代理にならない。本レポートが
Android Chrome 系の唯一の実測値である。

## 計測条件

| 項目 | 値 |
| --- | --- |
| 端末 | Galaxy Fold8 Ultra |
| OS / バージョン | Android 17（UA 表記は Android 10 / `Linux armv81`） |
| ブラウザ / バージョン | Chrome（UA は `Chrome/152.0.0.0`） |
| 回線 | Wi-Fi |
| 計測日 | 2026-09-12（UTC 03:00:48、`createdAt` より） |
| 成果物版（releaseId） | `c1-real-v1` |
| 計測方法 | 実機（`/bench?auto=1&upload=1`、本番 Cloudflare Workers） |
| 試行数 | 30 パターン × cold 3 回 / warm 3 回 = 180 試行 |
| メモリ出所 | `performance.memory`（Chromium は 10 MB 量子化、WASM リニアメモリを含まない） |
| 保存先 | R2 `bench/2026-09-12T03-00-48-319Z-unknown.json`（`device.json`） |

計測は本番 URL `https://shutoko-sim-workers.raiden000discord.workers.dev` に対して行った。
`engine.json` は再デプロイで投入済みのため cold が完走している。

補足:

- タイムアウト 0 件、エラー 0 件。候補件数の内訳は 2 件 96 試行 / 1 件 24 試行 / 0 件 60 試行
  （0 件は時間窓のフィルタ結果で、探索自体は成功している）。
- **探索 p95 は 289 ms**（代理計測の 222 ms より遅い）。これは代理計測の CPU スロットルが
  Worker に効かず「スロットルなしのデスクトップ CPU」を測っていたためで、実機の方が
  正しく遅い。実機で測ってもなお目標 2,000 ms に対して約 7 倍の余裕がある。
- cold の初回候補 p95 は 1,860 ms、warm は 376 ms。差は成果物 5 件の逐次取得（8 RTT）で
  説明でき、代理計測（Fast 4G で 1,676 ms）と整合する。Wi-Fi のため Slow 4G 代理計測
  （5,916 ms）より速い。
- 外れ値: `yurakucho-mid` の cold 1 試行のみ初回候補が 30,194 ms だった。同じ試行の
  `tSearchMs` は 640 ms で正常であり、初回候補表示までの間に端末側の一時停止
  （サスペンド・GC・バックグラウンド化など）が入ったとみられる。p95（90 試行中の上位
  5% = 5 番目）には影響しない。
- cold 転送量は Worker 側 `transferSize` 合計の最大 402,531 B + pageLoad 分 2,274 B。
  代理計測の 405.7 KiB とほぼ一致し、10 MiB 予算に対して約 22 倍の余裕がある。

## 代理計測との比較

| 目標 | 実機（Galaxy Fold8 Ultra / Wi-Fi） | 代理（Pixel 5 相当 / Fast 4G） | 代理（Slow 4G） |
| --- | --- | --- | --- |
| 探索 p95 | 288.7 ms | 222.0 ms | 221.1 ms |
| 初回ロード p95（cold） | 2,242.6 ms | 1,999.1 ms | 6,572.4 ms |
| cold 転送量 最大 | 461.7 KiB | 405.7 KiB | 405.7 KiB |
| 探索ピークメモリ | 9.5 MiB | 9.5 MiB | 9.5 MiB |

- 探索時間は実機の方が 30 % 遅い。代理計測が Worker のスロットルを再現できない既知の限界
  （`../README.md` の 4-2）どおりで、実機値が真の値である。
- 転送量の差（461.7 / 405.7 KiB）は、ローカル `wrangler dev` の圧縮が本番エッジより
  11.3 % 小さい既知の差（`../README.md` の 4-4）と整合する。本実機計測は本番エッジの
  実測値である。
- メモリは両者 9.5 MiB だが、`performance.memory` の 10 MB 量子化と WASM リニアメモリ
  除外により、128 MiB 判定は粗い近似である。

## 判断

- **目標に対する合否**: 4 目標すべて PASS。実機（Galaxy Fold8 Ultra / Android 17 / Chrome /
  Wi-Fi）で、探索 p95 289 ms・初回ロード p95 2,243 ms・cold 転送量 462 KiB・
  ピークメモリ 9.5 MiB を確認した。
- **代理計測の扱い**: 代理計測の 4 目標 PASS は暫定であったが、実機計測でも同じく PASS と
  なり結論は変わらなかった。探索時間は代理計測が実機を再現できていないため、実機値を
  正として採用する。
- **Web Worker 実行方式の判断**: **維持する**。探索 p95 が目標の約 7 倍の余裕を持って
  収まり、Slow 4G 相当でも代理計測で初回ロードが 8 秒以内（6,572 ms）に収まっている。
  [サーバー実行の代替案](../../architecture.md)へ切り替える根拠はない。
- **次のアクション**:
  - iOS Safari は端末未所有のため未計測（本アプリは個人利用のため対象外とする）。
  - Slow 4G 相当の実回線（モバイルデータ）での初回ロードは未計測。Wi-Fi で 2,243 ms、
    Slow 4G 代理で 6,572 ms であり、実回線での確認は今後の任意項目とする。
  - 候補 0 件となるパターンが 60 試行あった（時間窓による除外）。計測上の問題ではないが、
    時間条件の既定値は利用者にとって分かりにくい可能性があり、#15 の UI 検討材料とする。
