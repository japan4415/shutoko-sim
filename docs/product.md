# プロダクト企画

## 出発地点に戻るまでの時間で、首都高の周回候補を探す

出発前に「60〜90分ほど、首都高を走りたい」と考えるドライバーが、自分で入口・出口や周回経路を調べずに済むようにする。候補の時間には、出発地点から入口までの一般道、首都高の周回、出口から出発地点に戻る一般道を含める。帰着先は原案では未指定だが、初期版では出発地点とする。

[原案](original.md)は、首都高を1周した上で入口の1区間先で降りると、入口・出口の1区間分の料金になるという考え方を出発点にしている。アプリでは、地図に描く周回と、公式料金表が示す入口・出口間の料金を分ける。公式料金表との照合は、周回したときの実際の ETC 請求額を確かめたことにはならない。[神田橋入口 → 宝町出口の検証手順](delivery.md#神田橋入口から宝町出口まで実機と実走を別に検証する)で、ナビの再現性と実走後の明細を別々に判定する。原案は人間のみが編集する。

## 検索結果からわかることと、わからないこと

- **出発地点**: 住所検索、現在地、地図、座標で指定できる。国土地理院の住所検索を使い、駅名や施設名（POI）で探す機能は提供しない。入口・出口を指定する検索もあり、選べるのは対応する一般ランプに限る。
- **時間**: 最小は余裕なしの推定時間、最大は余裕込みの計画時間で判定する。一般道の距離・時間は直線距離をもとに概算し、実際の一般道ルートやライブ渋滞は反映しない。休憩は含めず、最小・最大とも最大240分まで指定できる。
- **料金**: 普通車 ETC 基本料金（割引適用前）に限る。入口・出口の公式料金は「最低料金」や実際の請求額としては示さない。公式料金の根拠がなければ未算出とし、OSM の走行距離から金額を作らない。
- **地図**: 既定の 2D 地図には国土地理院のタイルを使い、首都高の道路データには OpenStreetMap（OSM）を使う。3D は実験的な別タブのプレビューで、探索や地図確認に必須ではない。

座標検索は、近くて構造上使える入口を距離順に評価する。近い入口で周回自体はできるものの時間枠に入らないとわかった場合は、その入口での結果を返す。離れた入口から時間枠に入る周回が見つかることはあるが、自動で探し直すわけではない。比較対象はこの探索で得た最大3件。料金を確認できた商品候補同士は1円で走れる首都高の時間で比較し、全入口・全経路での最適解とは表現しない。[時間判定と東京駅の例](routing.md#東京駅の実測と最近接入口の契約)を参照。

## 道路を探索できる範囲と料金付きで薦められる範囲は違う

グラフには首都高の全24路線が入っているが、すべての入口・出口を使えるわけではない。向きと接続の根拠がある一般ランプのうち、周回へ接続できるものが探索対象となる。境界JCT、閉鎖箇所、接続が未確認のランプなどは選択対象外。島しょ部のように道路で接続できない地点は対象外とし、遠すぎる出発地点には入口までの直線距離を案内する。

公開版とローカル生成物の両方に、データ上検証済みの課金ペア13件（C1 8、C2 3、2号放射線ルート2）と未検証1件（芝公園入口 → 飯倉出口）がある。これはカタログ上の数で、1回の検索で返す候補数ではない。時間と道路の接続を確認できても、商品適格性を確認できない組み合わせは参考候補（`topology_only`）であり、商品推薦から外す。

料金付きでも、Google マップでの再現性は別の条件で判断する。2号放射線ルートの分割引き継ぎは実機検証が揃うまで無効。C1 legacy の単一リンクには、未検証の組み合わせが残る旨を示す。ナビに従う前に、停車中に周回の向きと入口・出口を確認してもらう。

初期版は一度入場し、一周後に一度退出する周回を扱う。周回に必要な同一区間の再通過は認める。ライブ交通情報、割引込みの料金最適化、別地点への帰着、追加周回、休憩、走行中の再探索、自前ナビ、履歴管理、全国対応は初期版の対象外。

## 成功の判断

代表地点と時間枠を固定し、時間と入口・出口が期待どおりかを再現できるか確認する。利用者テストでは、5人中4人以上が補助なしで条件入力から候補選択まで進み、周回経路と料金の根拠を区別できることを暫定目標とする。小規模な利用者テストを市場適合の証明には使わない。

運用では検索完了率、候補なし率、候補選択率、出発操作率を集計する。出発操作は Google マップを開く意思を示すだけで、実走の完了や請求額を示さない。利用者の走行履歴は集めず、時間の納得感や候補の違いは任意の聞き取りで確かめる。次に確認する端末と公開条件は[実装・検証計画](delivery.md)に示す。
