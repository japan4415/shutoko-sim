# プロダクト企画

## 目的

首都高を1周して入口の1区間先で降りると、課金は1区間分になる。この[原案](original.md)の前提を利用し、限られた空き時間で首都高の周回ドライブをできるだけ楽しめるルートを検索・提案する。

価値の中心は、**課金対象は1区間でも、実際には首都高を周回して長く走れる**こと。利用者が周回経路や入口・出口の組み合わせを自分で調べなくても、時間予算に収まる候補を選べるようにする。

[原案](original.md)を最上位の前提とする。原案は人間のみが編集する。以下で補った判断は設計提案であり、発案者が確定した要件と区別する。

## 前提と今回の提案

| 区分 | 内容 |
| --- | --- |
| 原案の前提 | 首都高を1周した上で入口の1区間先で降りると、1区間分の料金になる |
| 原案の要件 | 住所または GPS の出発地点、最小・最大時間を入力する |
| 原案の要件 | 地図付き候補から選び、出発ボタンで Google マップを開く |
| 原案の技術前提 | Cloudflare Workers、Rust の WASM をビルドして R2 に配置、OpenStreetMap Japan による地図提示 |
| 今回の提案 | 首都高を降りた後、一般道で出発地点へ戻る計画を初期版の標準にする。原案は帰着先を指定していない |
| 企画仮説 | 普通乗用車・ETC 利用を対象とし、検証済みの限定道路網から始める |
| 今回の提案 | 1区間課金になる周回を候補の必須条件とし、時間予算の中で首都高を長く走れる候補を優先する |
| 技術提案 | R2 配信の WASM をブラウザ内で実行し、Workers は配信と住所検索の窓口を担う |

「OpenStreetMap Japan」は日本の OSM データを用いる意図と解釈する。特定のタイル配信契約や住所検索サービスが決まっていることを意味しない。

## 利用場面と価値

主な利用者は、出発前に「60〜90分ほど、安く首都高を走りたい」と考えるドライバー。出発地点から使いやすい入口を探し、首都高を1周し、入口の1区間先の出口で降りる候補を比較する。今回の帰着提案では、その後の一般道移動まで含む計画時間を示す。

順位は、全候補の料金額が確認済みなら首都高走行時間/料金、未確認額が含まれるなら首都高時間を基準とする提案とする。詳細は[ルート探索設計](routing.md)に定義する。

初期版は実走行の総所要時間・距離、首都高走行時間、一般道時間と、課金対象となる入口・出口の1区間を区別して提示する。周回成立のための区間再通過は認め、重複の排除を目的に周回を壊さない。景色や楽しさを客観的に採点できるとは仮定しない。上位候補は「探索した候補内でのおすすめ」であり、全道路・全条件での最適解とは表現しない。

料金規則は原案の前提として採用する。一方、具体的な入口・出口が「1区間先」に当たるか、走行方向が接続するか、適用する車両・支払い条件と料金額は、候補を提供するためのデータ検証事項とする。料金額を未取得でも「課金対象: ○○入口→△△出口の1区間」「料金額: 未算出」と表示し、安く長く走る仕組みを伝える。入口・出口の適用関係を検証できない候補は出さない。1区間の金額が全候補で同じとは仮定しないため、金額未取得の候補間で円当たりの効率や金銭的な最安は断定しない。

## 初期版の範囲

住所の確定検索または現在地取得、1分単位の時間指定、1区間課金になる周回の探索、最大3件の候補比較、実走行経路の地図表示、Google マップへの引き継ぎを一連で提供する。今回の設計では帰着までを時間予算に含めるが、帰着方式は実装前に確認する提案である。候補が少ない場合は水増しせず、見つからない場合は条件の変更を案内する。

対象地域はデータ成果物の対応範囲で公開する。具体的な入口・出口・JCT と1区間の組み合わせは先行検証で決め、未検証の首都高全域対応を掲げない。初期版は一度入場し、1周して1区間先で一度退出する経路に限定する。周回成立に必要な区間の再通過と、時間を埋めるだけの追加周回を区別し、複数周への拡張は後続とする。

ライブ渋滞予測、割引を網羅した厳密な料金最適化、別地点への帰着指定、複数周、休憩込みの計画、走行中の再探索、自前ナビ、ユーザー登録、履歴同期、全国対応は後続候補とする。

## 成功の判断

まず、代表地点と時間予算を決めた検証で、首都高を1周し、入口の1区間先で降りる候補が時間内に出るかを確認する。利用者テストでは、5人中4人以上が補助なしで条件入力から候補選択まで完了し、実走行は周回・課金対象は1区間と理解できることを暫定目標とする。母数が小さいため市場適合の証明とは扱わない。

運用では検索完了率、候補なし率、候補選択率、出発操作率を集計する。出発操作は Google マップへの遷移意図であり、実走行の完了や満足度を意味しない。走行履歴を集めず、任意の聞き取りで時間の納得感や候補の違いを評価する。

## 決定が必要な点

帰着方式、対象車両・支払い条件、対応地域、料金額の取得方法、1区間課金の条件を満たす候補同士の順位付けは実装前の企画レビューで確認する。「1周して1区間先で降りる仕組みを利用する」ことは未確定事項に戻さず、原案の前提として扱う。採用候補と判断時期は[実装・検証計画](delivery.md)に集約する。
