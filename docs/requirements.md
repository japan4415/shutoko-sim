# 機能要件とユーザー体験

[企画](product.md)に沿って、画面に表示する条件と、候補が出ないときの案内を定める。

出発地点から首都高を周回し、同じ出発地点へ戻る計画を探す。料金付きの商品候補は、データ上検証した1区間先の出口を使う。地図に描く首都高の周回、公式の入口・出口間料金、実際の ETC 請求は別々に扱う。

## 検索できる範囲と候補が成立する範囲

住所検索・現在地・地図・座標から出発地点を決める。国土地理院の住所検索を使い、駅名や施設名（POI）の検索には対応しない。入口・出口を指定する検索でも、周回に接続できる一般ランプだけを使う。閉鎖箇所や境界 JCT、接続を確認できないランプは選べない。島しょ部は道路で接続できないため対象外とする。

座標検索は、出発地点に近い入口のグループ（tier）から評価する。構造上使える近い入口で周回が見つかっても時間条件に合わない場合、遠い入口へ自動では切り替えない。全入口を横断した順位ではないことを結果と候補なしの案内に示す。入口を変えて調べるには、出発地点を変更するかランプ指定検索を使う。入口までの距離上限は Web 版で 46 km、探索コアの既定値は 30 km。上限を超える座標検索は `NO_CONNECTION` とし、最寄り入口までの直線距離を示す。

公開版・ローカル生成物とも課金ペアは14件あり、データ検証済み13件、未検証1件（芝公園入口 → 飯倉出口）。動的な入口・出口の組み合わせが道路の接続と時間の条件を満たしても、商品適格性の裏付けがなければ `topology_only` の参考候補とする。座標検索・片側指定・両端指定の違いは[ルート探索設計](routing.md)に定義する。

## 通常の流れ

| 段階 | ユーザーの操作 | システムの応答 |
| --- | --- | --- |
| 出発地点 | 住所を検索し候補を選ぶ、または現在地を取得 | 地図上の位置と住所を表示し確認できる |
| 時間 | 最小・最大を分で入力 | 一般道で出発地点へ戻るまでを含み、休憩を含まないことを表示 |
| 検索 | 「ルートを探す」を押す | 準備・探索状態とキャンセルを表示 |
| 比較 | 最大3候補のカードを選ぶ | 首都高の周回経路を強調し、入口、出口、主な通過路線を表示 |
| 詳細 | 時間内訳、周回経路、課金対象を確認 | 地図と同じ候補の詳細、推定条件と料金の根拠・取得状況を表示 |
| 出発 | 引き継ぎ可能な候補から Google マップを開く | ナビ開始前に、入口・周回方向・出口が一致するか確認を促す |

時間は `1 ≤ 最小時間 ≤ 最大時間 ≤ 240` 分の整数。往復が対象で、最小は余裕なしの推定時間、最大は余裕込みの計画時間で判定する。一般道は直線距離をもとにした概算で、道路に沿った経路やライブ渋滞、当日の通行規制、休憩は計算に含めない。[時間の計算式](routing.md#時間条件現行-c1-legacy-と-routing-v2-の共通式)を参照。

現在地はボタン操作時に一度だけ要求する。継続追跡しない。住所の入力途中に外部検索せず、検索確定時に送る。同名住所は候補から選ばせ、最初の候補へ無断で決定しない。位置精度が悪い場合は地図上の位置を確認してもらい、住所検索に戻れる。

## 候補の表示内容

カードは余裕なしの推定時間と余裕込みの計画時間を分け、一般道の往路・復路と首都高時間の内訳を示す。距離は首都高の周回距離を示し、往路・復路それぞれの推定距離を持つ場合だけ「往復距離（概算）」も表示する。`LegacyCandidate` は互換仕様のため `distanceMeters` と `shutokoDistanceMeters` が同じ首都高距離であり、前者を往復距離に読み替えない。

料金付きで検証済みの商品候補には「課金対象: ○○入口 → △△出口の1区間」と表示する。`billingDistanceMeters` が正の有効値なら「料金表上の距離」も示す。金額が未確認の商品候補は入口・出口名だけを示し、課金対象とは断定しない。料金には「普通車 ETC 基本料金（割引適用前）」を使い、「最低料金」や実際の請求額としては表示しない。「料金効率 n 位」は、料金付きの商品候補を1円あたりの首都高走行時間で比べた順位で、「最安順位」ではない。`TopologyOnlyCandidate` は「参考経路・料金の比較対象外」として区別し、料金根拠がなければ未算出とする。

既定の 2D 地図は国土地理院のタイルを背景に、OSM 由来の首都高の経路を描く。3D は別タブの実験的なプレビュー。放射線候補の4区間はカードと同じ番号・名称・線種で示し、一般道の概算を実在の道路線として描かない。2D・3D とも、料金表上の距離から位置を推定した線は描かない。料金の根拠は入口・出口名と料金表上の距離をテキストで示す。

Google マップの引き継ぎが使えるかは料金とは別に判定する。C1 legacy の単一リンクには実機未検証の注意を出す。放射線候補の3分割リンクは実機検証ゲートを満たすまで出さず、理由を表示する。いずれもアプリ側で周回の再現や実所要時間を保証しない。出発前に経路を確認する。

候補の地図とカードは同じ候補 ID に結び付ける。条件変更時は選択と出発リンク、前回の探索結果に基づく復帰導線を失効させ、旧条件の結果で出発できないようにする。検索中の再入力では古い結果を採用しない。結果取得前の成果物不一致・通信失敗の再読み込み案内は条件変更では消さない。

## 例外と復帰

| 状態 | 応答と復帰手段 |
| --- | --- |
| 時間の逆転・小数・空欄 | 対象欄に理由を示して検索しない |
| GPS 拒否・取得失敗 | 住所検索を使える。許可要求を繰り返さない |
| 住所候補なし | 都道府県から住所を入れ直すか、現在地・地図を使うよう案内し、時間入力は保持 |
| 対応地域外・入口アクセス地点なし | 対応範囲を表示。近い高速道路へ直線接続しない |
| 候補なし | 候補が見つからなかった原因を示す。既知の最短周回が最小時間で除外されている場合は、その周回を下限に含められる値まで最小時間を下げる操作を案内する（既知周回が製品下限 1 分未満でどの最小時間でも含められないときは出さない）。上限で除外されている場合は最大時間を広げる操作を案内する（上限が製品上限 240 分のときは拡大を案内しない）。製品上限 240 分以内の合法な周回が無い場合は時間拡大を案内せず、出発地点の見直しを案内。打切り等で時間変更の効果が証明できず、かつ上限が製品上限 240 分で拡大もできないときだけ時間操作を出さず条件の見直しを案内する（上限が 240 分未満なら、変更後の値が変わる拡大操作は候補の可能性として案内してよい）。押下時に現在値と比較し、値が変わらない操作・引上げを成功として告げない。いずれも自動変更しない |
| 入口・出口の適用データ未検証 | 商品推薦に含めない。道路上の接続と周回を確認できる組み合わせは参考候補として区別し、単なる短距離経路は代わりに出さない |
| 探索上限到達 | 打切りは確定した事実として示し（`status: "truncated"`）、検証済み候補だけ表示。候補がある場合は一部の候補だけであることを伝える。候補なしと経路不存在を同一視しない。候補0件なら時間枠の拡大を偽らず、同じ条件の再試行は同じ結果になるため出発地点や条件の変更を第一導線に、再試行を補助として案内する |
| データ/WASM 不整合・通信失敗 | 再読み込みを案内。部分データで探索しない |
| 地図取得失敗 | 条件を保持して再試行。地図確認ができるまで出発を無効化 |
| 引き継げない経路 | URL を構成できない場合は探索結果に理由を示す。実機検証ゲートが閉じている放射線候補はカードを残し、引き継ぎボタンを出さず理由を表示 |
| 外部アプリがない | Google マップの Web 版を利用。Web 版でも周回を維持できるか実機で確認する |

## 操作性の要件

スマートフォンの縦画面を中心に、入力、候補、詳細の順で情報を並べる。地図だけで操作を完結させず、候補はテキストでも選べるようにする。色以外に番号・線種・選択状態で区別し、各入力にラベル、エラーに読み上げ可能な説明を付ける。キーボードで入力・候補選択・出発ができ、進捗と完了を支援技術に通知する。

Google マップには実走行の周回を維持する経由地点を渡す。入口と出口だけを渡して、周回を省いた1区間の最短経路にならないようにする。経路や所要時間が変わる可能性があるため、出発前に周回経路・入口・1区間先の出口・経由地点を確認する流れとする。走行中の継続操作は設計に含めない。

## 受け入れ条件

住所と現在地の双方で条件を確定して検索できること。商品候補と参考候補を区別し、引き継ぎについては次の条件を満たすこと。

- 商品候補は首都高を1周し、入口の1区間先としてデータ上検証した出口で降りる。課金対象と、地図に示す周回経路を区別できる。
- 往復を含む時間判定と表示の内訳に矛盾がない。推定値を実測として表示しない。
- Google マップへの引き継ぎは実機ごとに確認する。短距離経路への置き換わり、入口・出口の変更、周回方向の逆転を見落とさない。

候補なし、位置拒否、圏外、地図失敗、検索キャンセルから再操作できること。外部への引き継ぎについては[検証計画](delivery.md)の実機確認を公開条件とする。
